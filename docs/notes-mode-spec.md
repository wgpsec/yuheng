# 玉衡笔记模式 Spec

状态：设计确认稿，按 slice 分阶段实施

目标版本：`0.2.x` 后续迭代

## 1. 背景与目标

玉衡目前有“对话”和“任务”两种工作区模式。新增“笔记”模式后，玉衡应成为一个本地优先的 Agent 工作台：用户可以沉淀长期资料、整理对话结果、管理任务上下文，并在同一套块编辑器中完成写作和 AI 协作。

笔记模式不是把任务卡片换成另一种列表，也不是把对话消息直接当作文档。它需要有独立的页面身份、层级、排序、正文和生命周期，同时复用玉衡已有的块编辑器、Provider、Profile、运行记录、附件安全边界、搜索和备份能力。

### 1.1 产品目标

- 在侧边栏的对话、任务之间新增笔记模式，模式切换不影响另外两种模式的当前选择和草稿。
- 提供接近 Notion 的页面树和块编辑体验：快速新建、层级组织、拖拽排序、自动保存和稳定的编辑反馈。
- 复用现有 Markdown 块编辑器作为唯一正文编辑入口，避免任务和笔记出现两套块行为。
- 让 AI 成为笔记的显式协作工具：总结、改写、扩展、提取任务等操作可追踪、可预览、可撤销。
- 笔记数据可以被全量备份、恢复和搜索，不引入云同步或账号体系。

### 1.2 非目标

- 第一阶段不实现多人实时协作、云同步、分享链接、权限系统或冲突合并。
- 不在本功能内重写 Tiptap 或另建一套 JSON Block 数据格式；Markdown 仍是正文权威表示。
- 不把笔记、任务和会话合并成一个含糊的“内容表”。三者保持清晰的领域边界。
- 不自动把所有对话或工具输出写入笔记；任何导入或 AI 写入都必须由用户触发。
- 不在笔记模式中复制一套 Provider、Profile 或 Agent Runtime；统一使用当前会话配置和现有运行链路。

## 2. 术语与领域边界

| 术语 | 定义 |
| --- | --- |
| 笔记（Note） | 一个可独立打开、编辑、搜索、归档和删除的页面实体。 |
| 页面树 | 通过 `parent_id` 和 `position` 组织的笔记层级；根笔记没有父页面。 |
| 块编辑器 | 当前 `MarkdownBlockEditor` 提供的受控 Markdown 编辑器及块工具栏。 |
| 笔记上下文 | 用户显式选择并发送给 Agent 的笔记标题、正文或选中文本。 |
| AI 操作 | 对笔记内容的单次生成或变更请求，必须产生可审计的运行记录。 |

任务仍然由 `TaskBoard`、`TaskType` 和任务状态机管理；笔记只在用户选择“提取为任务”后创建任务，并保留来源笔记关系。对话仍然由会话、消息和 Run 管理；笔记不会隐式变成会话消息。

## 3. 用户场景

### 3.1 记录与整理

- 用户点击“笔记”模式，看到最近打开的笔记和页面树。
- 用户新建根笔记，输入标题后立即进入正文编辑；空正文显示轻量空状态，不阻挡编辑。
- 用户在某个笔记下新建子页面，通过树状导航整理会议记录、研究资料和项目文档。
- 用户拖拽页面改变同级顺序，或拖入另一页成为子页面；禁止拖入自身或自己的后代。
- 用户删除页面时看到明确的影响范围；删除父页默认一并删除子树，必须二次确认。

### 3.2 块编辑

- 复用现有块编辑器支持段落、标题、列表、待办列表、引用、代码、分隔线、图片/附件（按切片启用）。
- 鼠标悬停块时显示块工具栏，工具栏与正文不重叠；工具栏区域保持可操作，不因移出正文立即消失。
- 块可以上下拖拽排序，拖拽过程中显示稳定的插入指示线和过渡动画。
- 编辑器在窗口拖拽区域之外明确标记为 `no-drag`，标题、正文、菜单和拖拽手柄都可以正常左键操作。
- 内容以 Markdown 保存；加载时恢复为同样的块结构，未知 Markdown 不丢失原文。

### 3.3 AI 协作

- 用户在笔记标题栏或块菜单打开“AI 操作”，选择总结、改写、扩展、提取任务或自定义请求。
- 默认将当前选中文本作为上下文；未选中时由用户确认是否发送整页，避免大文档被意外发送。
- Agent 返回结果先进入预览态，用户可以“应用到原文”“插入到光标处”或“取消”；不允许静默覆盖正文。
- “提取为任务”创建任务草稿，预填标题和正文，用户确认后写入任务看板，并记录来源笔记 ID。
- AI 操作沿用当前 Provider、Profile 和推理级别；助手 Profile 的时间上下文策略保持现有规则。

## 4. 信息架构与交互设计

### 4.1 工作区模式

将现有 `WorkspaceMode` 扩展为：

```ts
type WorkspaceMode = 'conversation' | 'tasks' | 'notes';
```

侧边栏模式切换保留当前图标优先的 Notion/Codex 风格：未选中时显示图标，选中时显示“对话”“任务”“笔记”文字。笔记使用 `NotebookPen` 或同类 lucide 图标，不使用手写 SVG 或文字字符代替图标。

模式切换要求：

- 笔记模式拥有独立的 `activeNoteId`、树展开状态、搜索词和滚动位置。
- 切换模式时不销毁另外两个模式的编辑草稿、活动任务看板或会话选择。
- 从任务、对话跳转到笔记时，可以带入目标笔记 ID；目标不存在时显示可恢复错误，不改变当前模式状态。
- 刷新或重启后恢复上一次模式和各模式的独立选择；首次使用默认进入对话模式。

### 4.2 笔记模式布局

桌面布局采用三段式但不嵌套卡片：

1. 笔记导航栏：新建按钮、笔记搜索、页面树、归档入口。
2. 编辑主区：页面标题、保存状态、块编辑器和页面级操作。
3. 可选 AI 面板：只有用户打开 AI 操作时出现；默认不占用编辑区宽度。

页面树行为：

- 根节点按 `position` 排序；子节点按同样规则排序并缩进显示。
- 每个节点悬停显示省略号菜单；新建子页使用加号或菜单命令。
- 当前页高亮只作用于笔记导航，不改变对话或任务的选中样式。
- 页面树可收起，收起状态保存在本地 `localStorage`；树过长时使用虚拟滚动或分页，不能让整个工作区失去响应。
- 搜索笔记时暂时显示扁平匹配结果，点击结果后回到树中并展开其祖先路径。

编辑主区：

- 标题使用页面级 heading token，不使用任务卡片的紧凑字号。
- 正文宽度保持可读行长；窄窗口下允许换行，不通过缩小字体解决溢出。
- 标题、正文和块工具栏所在容器全部设置 `no-drag`。
- 自动保存时显示“保存中/已保存/保存失败”；失败状态提供重试，不丢失内存草稿。

### 4.3 空状态与删除

- 没有笔记时，主区提供一个直接的新建入口和简洁空状态；不展示营销式说明或大面积装饰。
- 新建笔记默认标题为“未命名笔记”，首次输入正文后可自动生成短标题，但用户改过标题后不得覆盖。
- 删除操作必须有确认；删除父页显示子页面数量。删除失败时保留当前页面和编辑内容。
- 归档是软删除，默认不出现在树中；归档页可恢复或永久删除。

## 5. 数据模型与持久化

### 5.1 SQLite 表

新增 `notes` 表，建议结构如下：

```sql
CREATE TABLE IF NOT EXISTS notes (
  id TEXT PRIMARY KEY,
  parent_id TEXT REFERENCES notes(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT '',
  position INTEGER NOT NULL DEFAULT 0,
  archived INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
CREATE INDEX IF NOT EXISTS notes_parent_position_idx
  ON notes(parent_id, archived, position, id);
```

约束：

- `id` 由主进程生成 UUID；Renderer 不生成或选择数据库 ID。
- `parent_id` 只能指向当前存在的笔记；移动操作必须在事务中检查环路。
- `position` 只表达同级顺序，重排时由主进程重新编号，避免浮点排序漂移。
- 标题和正文允许 Unicode，但必须限制长度；正文上限至少应高于单次编辑器可承载范围，并在 IPC 层再次校验。
- `updated_at` 由主进程写入，不能信任 Renderer 传入的时间。

### 5.2 搜索索引

将笔记标题和正文接入现有全局搜索索引：

- 搜索类型新增 `note`，上下文显示“笔记”。
- 插入、更新、归档、删除均通过 SQLite trigger 或统一索引函数保持同步。
- 搜索结果只返回必要的预览文本，不返回隐藏的运行输入、API Key 或文件路径。
- 搜索空查询仍遵循现有最近内容策略，但笔记按 `updated_at` 与对话、任务统一排序。

### 5.3 备份与恢复

在现有全量备份快照中增加 `notes` 数据集和 `data/notes.json`：

- 旧备份缺少 `data/notes.json` 时按空数组恢复，不影响已有会话和任务。
- 导入笔记生成新的笔记 ID，同时重映射 `parent_id`，不能覆盖现有页面。
- 如果引入笔记附件，再增加受控 `note-assets/` 目录；第一阶段可暂时复用现有受控资产管线，但不得把任意路径写入 Markdown。
- 笔记备份中不包含 Provider 密钥、SecretStore 内容、临时文件或未受控 workspace 文件。
- 只有当数据格式语义发生不兼容变化时才升级备份格式版本；新增可选数据集保持向后兼容。

## 6. Electron IPC 与前端合同

在 `desktop-bridge.ts` 增加类型化接口，所有实现放在主进程：

```ts
notes: {
  list: (includeArchived?: boolean) => Promise<Note[]>;
  get: (id: string) => Promise<Note | null>;
  create: (input?: { title?: string; parentId?: string }) => Promise<Note>;
  update: (id: string, patch: { title?: string; content?: string; archived?: boolean }) => Promise<Note>;
  delete: (id: string) => Promise<void>;
  move: (id: string, parentId: string | null, targetId?: string) => Promise<Note>;
};
```

合同规则：

- 参数在 IPC 边界做类型、长度和关系校验；Renderer 传入未知字段时忽略或拒绝。
- `list` 返回树构建所需的最小字段；正文通过 `get` 按需加载，避免页面树加载大文档。
- 更新接口支持幂等重试；保存失败时返回结构化错误，不泄露 SQLite 路径或密钥。
- 删除、移动、归档和恢复都必须触发统一刷新事件，避免多个窗口出现旧树。
- 所有笔记操作都不直接调用 Provider；AI 请求仍经由现有 Pi Runtime。

## 7. 块编辑器复用方案

当前 `MarkdownBlockEditor` 已经包含 Tiptap 实例、Markdown 序列化、块工具栏、拖拽手柄和资产回调。实现笔记模式时应先做小范围抽取：

- 将组件重命名或抽取为通用 `BlockEditor`，保留 `MarkdownBlockEditor` 兼容导出，避免一次性修改任务页面。
- 通过 props 控制 `placeholder`、`aria-label`、资产能力、只读状态和内容最大长度。
- 任务和笔记共享同一套扩展列表、Markdown 解析和块拖拽行为；修复一处即可覆盖两种场景。
- 编辑器只负责编辑和序列化，不负责保存、数据库、Agent 调用或页面树状态。
- 任何选区操作都使用 Tiptap/DOM 的结构化 API，不用字符串截取猜测块边界。

建议的通用接口：

```ts
type BlockEditorProps = {
  value: string;
  onChange: (markdown: string) => void;
  placeholder?: string;
  ariaLabel: string;
  readOnly?: boolean;
  onImportAsset?: (file: File) => Promise<ManagedAsset>;
  onPickAssets?: () => Promise<ManagedAsset[]>;
};
```

## 8. AI 能力设计

### 8.1 第一批动作

- 总结当前选区/整页
- 改写为更清晰的表达
- 扩展选区或继续写作
- 提取待办并创建任务草稿
- 自定义指令

每个动作都生成一个普通 Run，使用当前会话的 Provider、Profile 和推理级别。笔记不创建隐藏会话；Run 的来源字段记录 `noteId` 和操作类型，便于审计和恢复。

### 8.2 上下文与隐私

- 未选择文本时，整页操作必须显示范围确认；超长正文需要先提示截断或分段。
- 发送给 Provider 的上下文只包含用户选择的笔记内容和必要的标题，不自动附加整个笔记树。
- 助手 Profile 继续注入现有 runtime context；分析师和审计专家遵循各自 Profile 策略。
- AI 结果预览和工具记录按现有脱敏规则处理；不把 API Key、受控文件绝对路径或未授权附件传入 Prompt。
- 应用到原文前保留旧 Markdown 快照，支持一次撤销；失败或取消不得修改数据库。

### 8.3 后续 Agent 工具

第二阶段可以提供受控的笔记工具：`notes_list`、`notes_read`、`notes_create`、`notes_update`。工具默认关闭或仅在明确开启的 Profile 中暴露，并遵循现有 Browser Use/Computer Use 插件的可插拔原则。第一阶段不让 Agent 自主遍历整个笔记库。

## 9. 设计约束

### 9.1 视觉与排版

- 所有可读文字不低于 `13px`，遵循 [`ui-typography.md`](ui-typography.md)。
- 使用现有颜色 token 和主题；笔记页面不做单色渐变或装饰性渐变背景。
- 使用 lucide 图标；图标按钮必须有 `aria-label` 和 `title`。
- 不使用“圆角矩形 + 文字”替代已有的熟悉图标；页面操作优先使用图标按钮和上下文菜单。
- 页面区域使用全宽布局和约束内容宽度，不在卡片里再嵌套卡片。
- 标题、工具栏、正文和菜单的文字必须在窄窗口、高 DPI 和中英文混排时完整可读。

### 9.2 交互与动效

- 树展开/收起、模式切换、菜单和编辑器侧滑沿用现有过渡风格，默认 120-180ms；支持 `prefers-reduced-motion`。
- 拖拽时提供明确的目标高亮、插入线和放置反馈；禁止只改变透明度而没有空间反馈。
- 所有编辑区域设置 `no-drag`，避免 Electron 窗口拖拽层拦截点击。
- 菜单必须在卡片/树节点边界外可见，使用合适的 stacking context，不能被相邻内容裁剪。
- 键盘操作可完成新建、重命名、保存、搜索、撤销和删除确认；焦点移动有可见状态。

### 9.3 数据与安全

- SQLite 是笔记的权威存储；Renderer 只通过 typed preload bridge 访问数据。
- Markdown、标题、搜索词和 AI 输出都视为不可信文本；外部链接通过现有 URL 校验，禁止导入阶段执行 HTML/脚本。
- 写入采用主进程校验和事务；移动、删除子树和导入重映射不得留下孤儿页面。
- 自动保存不能覆盖用户最近一次成功内容；失败时保留草稿并提供重试。
- 所有新增能力保持本地优先，不引入新的远程服务、登录或密钥存储。

### 9.4 兼容性

- 旧版本数据库启动时自动迁移，迁移失败不得删除或覆盖现有会话、任务数据。
- 旧版本备份可以导入；没有笔记数据时按空列表处理。
- 现有任务编辑器和对话模式的行为、快捷键、字体和动画不能因抽取通用编辑器而回归。
- 新增笔记模式默认可用，不影响 Browser Use、Computer Use、桌面宠物等可插拔能力的开关。

## 10. Vertical Slices

每个 slice 都应包含主进程、bridge、Renderer、专项测试和最小可用交互；不要先堆一个只有 UI 的大分支。

### Slice 0：领域合同与迁移骨架

交付：

- 定义 `Note`、`WorkspaceMode` 和 typed bridge 类型。
- 新增 SQLite `notes` 表、索引、迁移和 AppStore CRUD 单元测试。
- 增加导出/导入快照中的 `notes` 可选数据集和旧备份兼容测试。

验收：

- 空数据库能创建根笔记和子笔记；重启后字段、顺序和归档状态保持。
- 父子关系不能形成环；删除父页按约定级联或事务回滚。
- 旧备份导入不报错，新备份包含笔记计数和数据集。

### Slice 1：笔记模式入口与空状态

交付：

- Sidebar 模式切换增加“笔记”图标和选中态。
- ProductionRenderer 增加 `notes` 分支、懒加载页面和独立 active state。
- 空笔记状态支持一键新建，保留现有对话/任务模式状态。

验收：

- 三种模式可以互相切换，切换过程中无重复 key、布局跳动或旧页面遮罩。
- 刷新后恢复上次模式；首次安装仍默认对话。
- 笔记模式所有可读文字和图标辅助信息符合排版标准。

### Slice 2：页面树与基础 CRUD

交付：

- 根页面和子页面列表、展开/收起、内联重命名。
- 新建同级/子页面、归档、恢复、删除确认和空树状态。
- 树状态、最近打开页面和搜索输入持久化到 localStorage。

验收：

- 页面树顺序与数据库 `position` 一致；刷新和重启后不乱序。
- 删除/归档失败不会丢失当前选择或编辑草稿。
- 归档页面不出现在默认树中，但可从归档入口恢复。

### Slice 3：通用块编辑器与自动保存

交付：

- 从任务编辑器抽取通用 `BlockEditor`，任务页面保持兼容导出。
- 笔记标题和 Markdown 正文编辑、占位符、受控更新、撤销/重做。
- 防抖自动保存、保存状态、失败重试和页面切换前的未保存保护。

验收：

- 任务和笔记的同一块操作产生一致 Markdown。
- 左键点击标题、正文和工具栏不会触发窗口拖动；块工具栏可以稳定悬停和拖拽。
- 快速连续输入不会出现旧内容覆盖新内容；保存失败后内存内容仍可恢复。

### Slice 4：页面拖拽与 Notion 风格交互

交付：

- 页面同级排序、跨父页面移动、拖拽目标高亮和插入线。
- 节点菜单、快捷新建、键盘导航和祖先路径展开。
- 模式切换、树展开、菜单和编辑器打开/关闭动画。

验收：

- 不能拖入自身或后代；非法放置不改变数据。
- 拖拽后树和主编辑区同步更新，跨窗口/快速连续操作不产生重复节点。
- `prefers-reduced-motion` 下功能完整但不播放非必要动画。

### Slice 5：笔记 AI 操作

交付：

- 选区/整页范围确认和 AI 操作菜单。
- 总结、改写、扩展、自定义指令和结果预览。
- 应用到原文、插入光标、取消、一次撤销；Run 关联 `noteId` 和操作类型。
- 提取任务草稿并跳转现有任务创建流程。

验收：

- 未经用户确认不会发送整页或修改正文。
- Provider 错误、取消和超时均保留原文，错误信息不泄露敏感数据。
- AI 操作使用当前 Provider/Profile/推理级别，运行记录可追踪但默认折叠。

### Slice 6：搜索、备份与跨模式关联

交付：

- 全局搜索索引笔记标题和正文，支持结果跳转并展开祖先路径。
- 完整备份导出/导入笔记及未来受控附件，保持旧包兼容。
- 从对话创建笔记、从笔记提取任务；保存来源关系和删除后的降级显示。

验收：

- 新建、更新、归档、删除后搜索结果实时正确。
- 导入生成全新笔记 ID，父子关系完整，不覆盖当前数据。
- 跨模式跳转不会丢失原模式草稿、滚动位置或活动运行。

### Slice 7：质量、可访问性与发布收尾

交付：

- 统一字号、颜色、焦点环、空状态和错误态。
- 桌面窄窗口、高 DPI、长标题、超长正文和大量页面树的视觉回归检查。
- 完整单元测试、IPC 集成测试、构建检查和更新日志。

验收：

- `npm run typecheck`、`npm test`、`npm run build` 全部通过。
- 关键交互有键盘路径和可见焦点；图标按钮有无障碍名称。
- 现有对话、任务、Browser Use、Computer Use、桌面宠物回归测试通过。

## 11. 测试矩阵

### 数据与迁移

- 创建、更新、归档、恢复、删除根页和子页；顺序和时间戳正确。
- 移动操作拒绝环路、未知父页和越权字段。
- 数据库重启、旧 schema 迁移和迁移失败回滚。

### 编辑器

- Markdown 往返序列化保留标题、列表、任务列表、代码、链接和图片占位。
- 快速输入、防抖保存、保存失败重试、页面切换和撤销。
- 块工具栏悬停、键盘导航、拖拽排序和减少动效模式。

### AI

- 选区上下文、整页确认、Provider/Profile/推理级别透传。
- 成功、取消、超时、错误和空结果都不破坏原文。
- 应用结果可撤销，Run 和脱敏活动记录正确。

### 搜索与备份

- 笔记增删改归档后索引同步；中文、英文和短查询可用。
- 新旧备份互导、ID 重映射、父子关系恢复、损坏包拒绝。
- 笔记备份不包含 API Key、SecretStore、临时文件或未授权路径。

### UI 回归

- 三种模式切换、独立状态恢复、菜单层级和动画。
- 980x640 最小窗口、常用 macOS 尺寸和高 DPI 截图检查。
- 所有可读文字不低于 13px；无文字溢出、遮挡、窗口拖拽拦截或重复 key。

## 12. 发布与文档要求

- 每个 slice 合并前更新本 Spec 的实施状态和对应测试。
- 新增 IPC、数据库字段和备份数据集必须同步更新 `docs/README.md` 或相关架构文档。
- 用户可见功能完成后补充 `CHANGELOG.md` 和应用内 release notes；版本遵循当前 `0.2.x` 迭代策略。
- 发布前执行类型检查、完整测试、生产构建和 macOS 安装包启动验证。
- 不在 Spec 或日志中记录 Provider 密钥、用户笔记全文或受控文件绝对路径。

## 13. 建议实施顺序

先完成 Slice 0-3，得到一个可创建、可组织、可编辑和可保存的笔记模式；再完成 Slice 4 的 Notion 风格交互。Slice 5 的 AI 操作必须建立在稳定的保存和撤销机制之上，Slice 6 统一处理搜索、备份和跨模式关联，最后用 Slice 7 做视觉和发布收尾。

第一版可交付标准是：用户能在笔记模式中创建页面树、使用现有块编辑器写作、可靠自动保存、重启后恢复，并可通过现有 AI 生成结果后由用户确认应用。附件、Agent 自主笔记工具和更复杂的 Notion 数据库视图均放到后续迭代。
