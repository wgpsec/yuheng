# 玉衡 v0.3.0 产品化实施计划

状态：Slice 1-2、Slice 4 已按 TDD 实施，Slice 3、5 待实施

目标版本：`0.3.0`

## 1. 背景

玉衡已经具备对话、任务和笔记三种工作区，笔记支持页面树、块编辑器、附件、图标、Cover 和页面级 AI 操作，任务支持看板、多视图、筛选和提醒，会话支持分支、运行记录、Provider 绑定和备份。

下一阶段重点从视觉仿制转向 Notion/Codex 中更有长期价值的工作流：内容互联、可控的 AI 修改、跨模块关联、异常恢复和 macOS 快速入口。

## 2. 产品原则

- 对话是入口，笔记是长期资料，任务是可执行结果；三者保持清晰边界。
- Markdown 仍是笔记正文权威表示，继续复用现有 Tiptap 块编辑器。
- AI 对内容的写入必须可观察、可确认、可撤销，不能静默覆盖用户内容。
- 本地优先，不引入云同步、多人协作、账号权限或完整 Notion 数据库体系。
- 优先复用现有 SQLite、搜索、Desktop Bridge、运行记录和备份能力；只有现有模型无法表达需求时才评估数据迁移。
- Renderer 不直接访问文件系统、SQLite、Provider 或外部网络，主进程继续作为本地数据和外部调用的写入边界。

## 3. 实施切片

### Slice 1：笔记页面链接与反向链接（P0）

#### 目标

让笔记从树状页面集合变成可以互相引用的本地知识网络。

#### 范围

- 在块编辑器中输入 `[[` 后提供页面搜索和选择；也支持将选中文本转换为页面链接。
- 侧栏页面菜单提供“复制页面链接”；复制的 Markdown 内部链接可直接粘贴到笔记正文并保持可点击。
- 链接在 Markdown 中保存稳定 Note ID，不使用标题作为唯一身份；标题修改后链接仍然有效。
- 点击页面链接打开目标页面，并让现有页面树、路径导航和选中状态同步更新。
- 页面底部显示反向链接列表，列出引用当前页面的笔记和所在上下文。
- 目标页面被删除或归档时，链接保留为不可用状态并显示明确文案，不执行隐式内容改写。
- 反向链接从现有笔记正文即时解析，不新增关系表；搜索和导航复用现有 `notes.list` / `search.query` 能力。

#### 验收

- 创建页面链接、重命名目标页面、移动目标页面后，链接仍可点击并打开正确页面。
- 同一页面被多个笔记引用时，反向链接去重且显示来源标题。
- 删除或归档目标页面不会让编辑器崩溃，也不会把正文中的其他内容删除。
- Markdown 导入、导出和旧笔记正文保持兼容；未知链接语法按普通文本处理。
- 键盘操作、鼠标点击、Escape 关闭选择器和无结果状态可用。

#### TDD

- 链接序列化/解析、ID 稳定性、标题变更和失效目标单元测试。
- 页面选择器的搜索、键盘选择、Escape 和点击打开行为测试。
- 复制页面链接与 Markdown 粘贴识别测试。
- 反向链接去重、归档/删除目标和页面树同步行为测试。

### Slice 2：AI 修改预览与可撤销应用（P0）

#### 目标

将笔记 AI 操作从“生成后直接替换”收敛为类似 Codex diff 的可审查变更。

#### 范围

- 总结、改写、扩展等已有操作继续使用当前 Provider、Profile、运行记录和取消机制。
- 生成结果先进入差异预览，用户可以接受、拒绝或撤销应用。
- 预览期间保留原正文；运行中显示明确状态，失败和取消不覆盖正文。
- 应用后保留一次可撤销快照，切换页面或关闭窗口时不丢失未处理预览。
- 不新增 AI Agent、Provider 协议或服务端实体。

#### 验收

- 流式结果到达期间用户能区分“生成中”和“已应用”。
- 接受只修改当前版本；正文在生成期间被用户修改时拒绝过期应用并提示重新生成。
- 拒绝、撤销和运行失败均恢复/保持原正文。
- 运行记录可追踪操作、状态和错误摘要。

#### TDD

- 版本冲突、接受/拒绝/撤销、取消和失败状态测试。
- 预览面板键盘和鼠标操作测试。

### Slice 3：任务、笔记、会话关联（P1）

#### 目标

形成“对话捕获 → 笔记沉淀 → 任务执行”的闭环。

#### 范围

- 从笔记块创建任务，任务保留来源笔记入口。
- 从任务返回来源笔记；从会话创建的任务继续保留来源会话和原消息入口。
- 全局搜索结果展示关联上下文，并支持跨模式跳转。
- Agent 的任务工具写入继续生成结构化回执，不自动把所有运行内容写入笔记。
- 优先复用已有 `sourceConversationId`、Note ID 和搜索结果模型，不建立含糊的统一内容表。

#### 验收

- 三种入口创建或打开关联内容时，当前模式、页面树和侧栏选中状态一致。
- 删除或归档来源内容后，关联入口显示“来源不可用”，不伪造新链接。
- Agent 创建任务和用户手动创建任务的关联行为一致且可审计。

#### TDD

- 关联创建、跳转、删除/归档来源和搜索投影测试。
- 会话、笔记、任务切换的公开行为测试。

### Slice 4：编辑与数据可靠性收口（P1）

#### 目标

让长时间使用、异常退出和备份恢复不会破坏用户内容。

#### 范围

- 自动保存采用有序队列，失败可重试，旧保存结果不能覆盖较新的编辑。
- 页面切换、关闭窗口和应用退出时处理待保存内容；不强制等待外部 AI 运行。
- 异常退出后恢复最近一次未提交编辑，恢复入口由用户明确确认。
- 备份恢复继续校验 manifest、附件 URL、页面父子关系和链接 ID；损坏数据部分失败时不影响其他数据导入。
- 不引入云同步、跨设备冲突合并或后台常驻同步服务。

#### 验收

- 快速连续编辑只产生最终有序结果；网络/IPC 失败不会回滚新内容。
- 重启、关闭和切换页面后，已确认保存的内容完整可读。
- 备份 round-trip 后页面层级、内部链接、任务关联和会话关联保持一致。
- 损坏附件或单条坏记录被隔离并有明确报告，不生成半写入文件。

#### TDD

- 保存竞态、失败重试、退出恢复和备份 round-trip 测试。
- 迁移失败回滚和部分损坏导入测试。

### Slice 5：macOS 快速入口与捕获（P1）

#### 目标

减少记录任务、笔记和想法的操作路径，让玉衡更像常驻的个人秘书入口。

#### 范围

- 扩展现有 `Cmd + K` 命令面板：快速新建会话、笔记、任务和打开最近内容。
- 菜单栏驻留状态下提供“快速记录”入口，打开主窗口并聚焦对应编辑器。
- 通知点击继续定位到任务或页面；不在后台自动执行高风险操作。
- 快速捕获默认落入收件箱或用户选择的目标，不改变现有任务/笔记实体。

#### 验收

- 主窗口和菜单栏两种入口均可在不丢失当前草稿的情况下创建内容。
- 快捷键冲突、窗口关闭、驻留关闭和通知点击均有明确行为。
- 应用未运行时不声称可以执行后台 Agent 任务；重新启动后只恢复本地内容和提醒。

#### TDD

- 命令面板动作、菜单栏入口、窗口聚焦和通知路由行为测试。
- macOS arm64 打包后的 IPC 白名单和启动恢复检查。

## 4. 实施顺序与发布门禁

按 `Slice 1 → Slice 2 → Slice 3 → Slice 4 → Slice 5` 顺序实施。每个切片独立完成公开行为测试、类型检查、构建和差异检查后再进入下一切片。

`v0.3.0` 发布前必须通过：

- `npm test`
- `npm run typecheck`
- `npm run build`
- `git diff --check`
- 关键页面在 macOS arm64 开发包中完成一次人工流程检查。

## 5. 本版本不做

- 云同步、多人协作、分享链接、账号权限和跨设备冲突合并。
- 完整 Notion 数据库、公式、自动化工作流和第三方日历同步。
- 新的 Worker 协议、远程 Agent 服务或替换 Pi runtime。
- 未经用户确认的 AI 内容写入、外部消息发送或高风险系统操作。
