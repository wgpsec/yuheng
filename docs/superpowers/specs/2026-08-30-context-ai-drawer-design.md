# 页面/看板上下文 AI 抽屉

状态：已按 TDD 实施，待最终审计

## 目标

在笔记页面和任务看板提供一个右下角的快速 AI 入口。点击后打开右侧抽屉，在不离开当前页面的情况下与玉衡对话，并自动携带当前页面或看板上下文。

## 范围与边界

- 笔记入口文案为“和此页面对话”，看板入口文案为“和此看板对话”。
- 抽屉由前端复用现有 Pi runtime/会话事件能力；不新增 Agent runtime。
- 页面上下文包含标题、正文和有效子页面引用；看板上下文包含看板名称、列名、任务标题、状态、优先级和截止时间。
- 上下文在每次发送时从当前快照构建并限制长度；不把附件二进制或无关全局会话注入模型。
- AI 回复默认只显示在抽屉中；只有用户明确点击“应用到页面/任务”时才调用现有写入入口。
- 不新增数据库表、字段或 Worker 协议。抽屉内的短期消息可保存在组件状态，关闭后清空；普通全局会话不被污染。

## 交互合同

1. 浮动按钮位于当前页面/看板内容区右下角，不遮挡滚动条和编辑控件；悬停显示 tooltip。
2. 点击后抽屉从右侧打开，顶部显示上下文来源和关闭按钮；原页面继续可见。
3. 发送后立即显示用户消息和“玉衡正在思考”状态；收到结果后显示助手消息。请求期间可停止，不能重复提交。
4. 空上下文、未配置 Provider 或请求失败时显示可理解的错误，不丢失已输入消息。
5. 抽屉关闭/切换页面时终止未完成请求；再次打开不复用其他页面的上下文。
6. 页面快捷操作（总结、改写、扩展、提取任务）继续留在页面右上角菜单；浮动按钮只负责自由对话。

## 页面应用边界

- 仅当 AI 返回明确的页面 Markdown 时显示“应用到页面”；应用前保留当前内容，可通过现有撤销能力恢复。
- 看板对话第一版只读，不提供批量写入；后续任务修改仍通过现有任务工具并要求用户明确确认。

## 验收与 TDD 矩阵

- 上下文构建：笔记/看板字段稳定、截断有界、无附件二进制和无关数据。
- 浮动入口：页面和看板各自显示，点击打开/关闭抽屉，切换资源不会串上下文。
- 发送生命周期：立即显示用户消息和 busy 状态，成功显示回复，失败保留输入并显示错误，停止后不再更新旧请求。
- 应用边界：默认不写入；页面应用需显式确认；看板对话不产生隐式任务变更。
- 兼容性：现有总结/改写等快捷 AI 操作、任务编辑器、笔记块编辑器和全局会话行为不变。

## 非目标

- 不实现多用户共享、云端同步、独立 AI 服务、附件理解或自动批量修改。
- 不改变 Pi runtime、Provider 选择、全局会话数据模型或任务/笔记持久化结构。

## 实施结果

- 新增可复用的页面/看板 AI 抽屉和右下角快速入口。
- 笔记使用当前页面快照；看板仅注入看板名称与任务元数据。
- 临时会话复用现有 runs API，支持 busy 状态、停止请求和旧请求结果隔离。
- 未新增数据库表、字段或 Worker 协议；默认不写入页面或任务。
