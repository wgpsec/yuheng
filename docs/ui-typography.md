# 玉衡 UI 排版标准

状态：生效

这份标准是玉衡所有新页面、组件和交互文案的排版基线。实现新界面或修改旧界面时，应优先使用全局 CSS token，不在业务组件里自行发明字号。

## 核心规则

- 所有可读的产品文字最小为 `13px`，包括正文、按钮、表单标签、菜单、提示、状态、计数和日期。
- 不使用 9px、10px、11px、12px 的文字来制造“紧凑感”；紧凑布局通过间距、留白和容器尺寸实现。
- 图标按钮只显示图标时不受字号规则约束，但必须有 `aria-label` 和 `title`（对用户不熟悉的图标）。
- SVG 图标使用图标库尺寸控制，不用文字字符代替图标。
- 标题通过字重、行高和层级区分，不使用负字距；`letter-spacing` 默认保持 `0`，只有标签型大写文本可以使用现有的正字距。
- 字号调整必须同时检查按钮高度、输入框高度、卡片固定高度、菜单定位和窄窗口换行。

## 推荐层级

| Token | 默认值 | 使用场景 |
| --- | ---: | --- |
| `--font-size-body` | `13px` | 正文、描述、列表项、日期和状态 |
| `--font-size-label` | `13px` | 表单标签、按钮、菜单项、筛选器 |
| `--font-size-caption` | `13px` | 辅助说明、空状态、计数、错误提示 |
| `--font-size-heading-sm` | `16px` | 区块标题、弹层标题 |
| `--font-size-heading-md` | `22px` | 页面标题、任务编辑标题 |
| `--font-size-heading-lg` | `25px` | 首屏欢迎标题等主标题 |

主题只负责颜色和对比度，不改变字号标准。需要更大字号时，应使用新的语义 token，并同步补充本文档。

## 组件约定

### 看板和列表

- 列标题、卡片标题、卡片正文和操作菜单不低于 `13px`。
- 卡片内容较多时限制行数或提供展开入口，不通过缩小字体塞入更多内容。
- 数量、日期、提醒等信息使用 `--font-size-caption`，不能使用极小字号。

### 表单和弹层

- 输入框、下拉框、标签和菜单项统一使用 `--font-size-label`。
- 弹层标题使用 `--font-size-heading-sm` 或更高层级。
- 字号变大后优先增加控件高度和内边距，避免文字贴边或被裁切。

### 技术信息

- 会话 ID、版本号、协议名等技术文本也保持至少 `13px`；可以使用等宽字体和较低对比度，但不能用更小字号替代层级。

## 开发检查清单

- 是否存在低于 `13px` 的可读文字？
- 是否优先使用了已有 typography token？
- 中文、英文、数字混排时是否会溢出或截断？
- 交互态（悬停、选中、错误、禁用）是否保持相同字号？
- 桌面窄窗口和高 DPI 下是否仍然可读？
- 新增字号是否需要同步更新组件文档和视觉回归截图？

全局渲染器样式已完成首轮迁移，当前不再保留低于 `13px` 的可读文字。后续新增页面不得绕过 token 引入更小字号；若确需新增层级，应先更新本文档并说明布局影响。
